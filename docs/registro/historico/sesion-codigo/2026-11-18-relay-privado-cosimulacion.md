# Relay privado de Cosimulación en Cloudflare

Se preparó el trayecto Fractal→engine→modelo dentro del Worker existente, sin abrir URLs de Containers ni depender de egress general. Se agregaron Durable Objects/Containers de Cosimulation Engine y modelo, con migración de DO `v3`. El `ContainerEgressProxy` valida el `COSIMULATION_INTERNAL_TOKEN` de 32–256 caracteres URL-safe en comparación de tiempo constante; permite solo crear/consultar jobs y `POST /v2/project`, rechaza otros hosts/métodos/rutas, y elimina el bearer antes de reenviar a cada Container. La llamada pública directa a rutas `/_internal/cosimulation/*` no existe. Fractal y engine envían el token al Worker; sin credencial el engine bloquea jobs y Fractal no configura el endpoint.

El workflow manual admite el secret opcional `COSIMULATION_INTERNAL_TOKEN`, lo valida sin imprimirlo y lo guarda en Cloudflare solo si está configurado; cada deploy calcula `COSIMULATION_RELAY_ENABLED` explícitamente para apagar el relay incluso si persistiera un secret anterior. Se añadieron pruebas de auth/routing, auth de solicitudes Fractal/engine y se actualizó la documentación. Validación local: typecheck Worker, 32 tests Worker, 53 tests Python dirigidos, Ruff, Wrangler dry-run y build/health smoke de los Containers de engine/modelo pasan.

No se ejecutó el workflow manual ni se tocó el secret remoto, D1 o una sesión PLC. La siguiente comprobación de Container→Worker→DO real exige configurar el secret y autorización explícita de despliegue; antes de esa prueba no hay modelo de Cosimulación en producción ni frames reales.
